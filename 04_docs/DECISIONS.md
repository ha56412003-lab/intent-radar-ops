## 2026-10-30 · 采集端从「油猴脚本」换成「ego(lite) + Agent」

**决策**：新链路用 ego(lite) 浏览器 + Agent 驱动，油猴脚本保留但不再是主路径。

**为什么换**：油猴脚本的死穴是**人必须开着那个页面**才扫得到。它省了"判断"的人工，没省"人在那儿刷"的人工。ego(lite) 让 Agent 在独立 Space 里用真实登录态自己开页面、自己滚、自己扫，两边不打架。

**顺带解决的**：原来 7 机部署（1 运营 + 1 老板 + 5 客服，每人装一套脚本）→ 现在**一台采集机**，客服零安装。

**代价（诚实记）**：
- 装机 + 每平台扫码 + 校准词库这 3 步永远要人，做不到零人工
- ego 窗口不能最小化（会被节流，页面不渲染）
- 机器得常开才能挂定时任务

**撤回方式**：`01_browser-scripts/` 里两个油猴脚本原样保留，工作台的 CSV 汇总入口也保留（`read_csv_glob` 还在）。要退回旧方式，把脚本装上、导出 CSV 丢进 `data/_incoming/` 即可。

## 2026-10-30 · 「回复」这一步永远不做自动化

**决策**：Agent 只负责「找到谁该回、该说什么」，**发送永远由人的手完成**。

**为什么**：
- 法务：全自动私信/评论引流在国内有刑事判例
- 平台：机器发的批量特征明显，封号率极高，号养半年一封不值
- 转化：话术值钱的地方就在"像真人"，机器发的第三句就露馅

**落到产品上**：工作台只给清单和话术，员工去 App 里发；工作台里只有一个「已回复」按钮用来记账，没有「发送」按钮。**这条线不做谈判。**

### 快手特别说明（诚实标注）

快手网页版结构**我这边拿不到**（机房 IP 被反爬挡，返回 JSON 错误），所以快手支持是**按通用规则接入**的，没有像抖音那样在真实页面上调过：

- 识别依据：卡片里的 `/short-video/<id>` 链接 + 通用文本扫描
- 已用模拟的快手结构（class 全混淆）验证：采集 3 条正确、雷达高亮 2 条、导航区和无关评论 0 误报
- **首次在真实快手页面用，请先扫一条视频确认**；不对就把「抓不到？点这里看页面结构」的截图发我，我照着调

快手对**下沉市场客户**（电瓶车、农机、五金、家居建材）价值很高，值得优先验证。


### 视频号的三个入口实测结论

1. **手机微信 App** — 有广场（推荐/朋友/关注），但要 ADB/无障碍自动化 = 群控，红线不动
2. **微信 PC 客户端** — 有广场（推荐页、搜索、评论），但它是**微信内置浏览器内核**，不是标准 Chrome，Tampermonkey 装不上
   - 想让脚本进去，唯一可行路径是「本地代理 + 根证书解密 + JS 注入」（wx_channel 这类工具）
   - **代价**：微信全部流量被中间人解密、违反用户协议、账号随时封、性质属破解客户端
   - **明确不做**
3. **channels.weixin.qq.com（视频号助手）** — 有网页版、能脚本化，但**只能管自己的号**（评论管理、私信、数据）
   - 角色是「承接」，不是「拓客」
   - 当前该号只有 2 个视频、1 条评论（"周杰伦好评"），接进去也无内容可扫

**一句话**：视频号能扫的地方只有人工手刷，没有自动化的合规口子。等它自己长出内容量了，再谈"养号承接"。
