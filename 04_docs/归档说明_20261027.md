## 二、四个新功能（本轮改动）

### 1. 两个卡片默认在屏幕右侧竖排

```
右上角  → 🎯 意向雷达（top:80px）
右侧中下 → 📡 作品清单采集（自动计算，避开雷达）
```

小屏幕上采集器会自动上移，不会跑出屏幕。

### 2. 两个卡片都能拖动，且记住位置

**拖标题栏**即可移动。松手后位置存进浏览器（localStorage），**下次打开还在原位**。

- 雷达位置存在 `yhradar_pos_v1`
- 采集器位置存在 `yhc_pos_v1`

想恢复到默认位置：浏览器 F12 → Console → 执行 `localStorage.clear()` → 刷新。

### 3. 采集内容自动去重（两层）

| 层 | 在哪去重 | 效果 |
|---|---|---|
| **脚本层** | 采集器记着采过的链接 | 同一页采第二次 → 显示「跳过重复 N 条」，不导出重复 |
| **工作台层** | `build.py` 按链接合并 | 多份 CSV 有重复 → 只算一条，构建时提示「已自动跳过重复作品 N 条」 |

**想重新采集全部**：点面板最下面的「清空去重记录」。

### 4. 防误改（三层防护）

⚠️ **先说实话**：Tampermonkey 的脚本**没有只读锁**，任何装上的脚本都能点进去编辑——这是这个工具的天性，改不了。所以我做了三层防护：

| 层 | 做法 |
|---|---|
| **① 劝退** | 脚本开头一大块 ⛔ 警告，点进编辑器第一眼就看到"请勿修改" |
| **② 降低误伤** | 关键数据集中放置，改动一处就整个坏掉（坏了一眼能看出来，不会"悄悄错") |
| **③ 能恢复** | 下面第三节，3 步恢复 |

**如果你的诉求是"绝对不能编辑"**，唯一办法是把脚本打包成浏览器扩展——但那样每次更新都要重新安装一遍扩展，比现在麻烦。**建议保持现状**：Tampermonkey + 这份母本文件备份，是维护成本最低的方案。

## 三、改坏了怎么恢复（3 步）

```
① Tampermonkey → 管理面板 → 把坏掉的那条脚本【整条删除】
② 找到母本文件，全选复制全文：
   雷达：  测试方向\意向雷达V1\意向雷达-评论区助手.user.js
   采集器：测试方向\获客工作台\采集器_获客采集.user.js
③ Tampermonkey → 添加新脚本 → 粘贴 → Ctrl+S → 关掉所有抖音/小红书标签页重开
```

**母本文件永远不要删、不要改**——它们就是"原厂备份"。

建议：把整个 `测试方向` 文件夹拷一份到 U 盘或网盘，双保险。

## 四、日常使用流程（一天）

```
早上
  1. 双击「启动工作台.vbs」→ 浏览器打开 http://127.0.0.1:8790
  2. 抖音/小红书搜「云南旅游」→ 按最多点赞排序 → 滚两屏
  3. 点采集器「采集当前页」→ 导出 CSV → 丢进 data\ 目录

白天
  4. 打开作品 → 雷达自动高亮意向评论
  5. 点评论右上角的彩色小圆点「话」→ 生成话术
  6. 复制 → 改两句 → 在评论区公开回复（点评论本身是正常跳转，不受影响）
  7. 回面板点「已回复 ✓」

收工
  8. 雷达点「导出记录 CSV」→ 丢进 data\ 目录
  9. 有私信进来 → 采集器在后台页抓一遍 → 导出 inbox CSV → 丢进 data\
  10. 重开工作台 → 漏斗自动更新

每周五
  11. 看「漏斗复盘」：回复率 / 回复→私信率 / 私信→留资率
  12. 看「需求池」：哪个问题被问 ≥3 次 → 做成内容
```

## 五、合规红线（别越线）

| 项 | 红线 |
|---|---|
| 发送 | **工具永不代发**，每条都由人的手指发出去 |
| 频率 | 小红书普通号 5 人/天、专业号 20 人/天；抖音同一陌生人 24h 只 1 条 |
| 内容 | 不在评论/私信里发微信号、手机号、二维码（触发风控） |
| 数据 | 只记录昵称、评论原文、作品链接；不抓手机号、UID、批量主页 |
| 采集方式 | 只在员工真实登录的浏览器里只读采集，不做服务器爬虫 |

## 六、行业包生成器（换行业 10 分钟出包）

**位置**：工作台左侧导航 → **🎁 行业包**（第 8 个页面）

### 怎么用

```
① 填行业名（如「电瓶车电池」）+ 关键词（一行一个）
   —— 关键词要填客户会说的具体词：换电池 / 锂电池 / 以旧换新，不要填「电瓶车」这种大类
② 点「生成行业包」→ 自动出 A级词 / B级词 / R级词 / 话术骨架
③ 人工过一遍，删掉不像人话的（这一步不能省）
④ 下载两个包，分别发给两个人：
      📡 雷达包_XX_客服装.user.js   → 客服装（扫评论、出话术）
      📋 采集包_XX_运营装.user.js   → 运营经理装（抓清单、抓私信）
```

### 核心机制：两段式判定（防误报）

```
第一道闸门（产品词）：评论里必须提到填的关键词，否则直接不算意向
第二道判定（意向词）：提到产品了，再看有没有「多少钱/能修吗/怎么买」这类意向词
```

**为什么这么设计**：一开始用"产品词+意向词"拼成一个词（如「电动车电池多少钱」），实测发现评论写「我的电动车电池跑不远了，能修吗」——中间夹了字，拼接词匹配不上，直接漏掉。
改成两段式后：提到「电动车电池」✅ + 提到「能修吗」✅ → 判为 A 级。

**实测（电瓶车电池，6 个关键词）**：

| 评论 | 判定 | 对不对 |
|---|---|---|
| 我的电动车电池跑不远了，能修吗 | A 级 | ✅ |
| 电池以旧换新多少钱一组 | A 级 | ✅ |
| 锂电池和铅酸电池哪个耐用 | B 级 | ✅ |
| 多少钱能买到好的（没提电池） | 不算 | ✅ 被产品词闸门挡住 |
| 这个视频拍得挺好看的 | 不算 | ✅ |

### 两个包的分工（给你的客户配人）

| 包 | 装给谁 | 干什么 | 验收标志 |
|---|---|---|---|
| **雷达包** | 客服（每人自己装） | 扫评论、高亮意向、出话术、记录已回 | 面板标题「🎯 XX 意向雷达」 |
| **采集包** | 运营经理 | 抓作品清单、抓各平台私信、导 CSV | 面板标题「📡 XX 作品采集」 |

### 一键换行业数据（现在是自动的）

生成器第 ④ 节有个 **⚡ 一键应用到工作台** 按钮（勾选框默认勾着）：

```
点一下 → 工作台自动做 5 件事：
  ① 把整个 data\ 备份到 data\_backup_时间戳\
  ② 写入 scripts.json / demands.json / staff.json
  ③ 清空 works.json / leads.json
  ④ 删除上个行业的 CSV（works_* / inbox_* / replies_*）
  ⑤ 重新构建 8 个页面
```

点完刷新「话术库」「需求池」，已经是新行业的了。

**实测结果**：点一次 → 写入 3 个文件、清空 2 个、删 4 个旧 CSV、页面全部切换成电池行业，旧旅游内容 0 处残留。

**两层安全网**：
- **写不进去就不动老数据**：如果三个文件一个都没写成功，接口直接报错返回，绝不执行清空/删除
- **每次自动全量备份**：回滚方法 = 把 `data\_backup_xxx\` 里的文件拷回 `data\`

**前提**：工作台必须用「启动工作台.vbs」启动（走 http://127.0.0.1:8790）。
如果双击 html 文件直接打开，这个按钮不能用——它需要一个本地服务接口来写文件。

> 三个 `下载 xxx.json` 按钮仍然保留，用于手动留档或给别的机器用。

### ⚠️ 生成的词是草稿，不是成品

自动生成的是**通用销售词表 + 关键词组合**，它不知道这个行业真正的痛点是啥。
**必须做的一件事**：拿到客户的账号，扫 200-300 条真实评论，看客户到底怎么说话，把真实的表达补进 A/B 级词里。
不做这一步，命中率会很平庸——这是这次验证里最值钱的一条经验。

## 七、还没做的（下一步候选）

| 项 | 说明 |
|---|---|
| 数据端全自动 | 现在靠人在搜索页点一下采集；全自动要买蝉妈妈/新榜 API（数百-数千/月） |
| 私信回复 | 现在只汇总展示，回复要跳各平台后台（合规要求） |
| 视频号广场 | 没有 Web 层，脚本进不去；只做自己号的承接 |
| 多租户/FDE 交付版 | 卖给客户时要隔离数据、单独打包 |
