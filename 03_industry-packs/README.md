# 行业包生成器

> **这个目录只是说明。功能已经做进工作台里了：打开工作台 → 左侧第 8 项「🎁 行业包」。**

---

## 为什么做成工作台里的一页，而不是独立工具

因为生成的东西要**直接落到工作台的数据里**——独立工具做不到"一键应用"，只能让你下载一堆文件再手工拖。

做成工作台的一页，就能：
- 读母本脚本（`01_browser-scripts/` 里那两个）
- 现场生成专属行业包
- 一键写进 `data/` 并重建页面

---

## 它怎么工作（架构）

```
工作台启动
  → build.py 读取 01_browser-scripts\ 里的两个母本
  → 把母本内容嵌进 pack.html（第 8 页）
  → 页面上的 JS 按你填的关键词生成词库/话术
  → 点「下载」得到两个 .user.js；点「一键应用」写进 data\
```

**母本脚本里的锚点**：

```js
// ==== INDUSTRY-PACK-START ====
  const INDUSTRY = "...";
  const PROD_WORDS = [...];   // 产品词闸门
  const A_WORDS = [...];      // 强意向词
  const B_WORDS = [...];      // 有兴趣
  const RED_WORDS = [...];    // 高风险
  const SCRIPTS = {...};      // 话术
// ==== INDUSTRY-PACK-END ====
```

生成器只替换这两行之间的内容，**其余几百行核心逻辑永不改动**。

---

## 怎么用（四步）

```
① 工作台 → 「🎁 行业包」
② 填行业名 + 行业关键词（一行一个）
     例：电瓶车电池 / 锂电池 / 换电池 / 电池以旧换新
③ 点「生成行业包」→ 检查自动生成的词，把不像人话的删掉
④ 下载并分发：
     📡 雷达包_XX_客服装.user.js    → 客服
     📋 采集包_XX_运营装.user.js    → 运营主管
     然后点「⚡ 一键应用到工作台」→ 话术库/需求池同步换掉
```

---

## 两段式判定（为什么不用拼接词）

**错误的做法**：把"产品词 + 意向词"拼成一个词（如「电动车电池多少钱」）。

**问题**：真实评论写「我的电动车电池**跑不远了，**能修吗」——中间夹了字，`includes` 匹配不上，直接漏掉。

**现在的做法**：
```
第一道闸门（PROD_WORDS）：评论里必须提到你填的产品词
第二道判定（A/B_WORDS）：提到了产品，再看有没有「多少钱/能修吗/怎么买」
```

实测（电瓶车电池）：

| 评论 | 判定 |
|---|---|
| 我的电动车电池跑不远了，能修吗 | A 级 ✅ |
| 电池以旧换新多少钱一组 | A 级 ✅ |
| 锂电池和铅酸电池哪个耐用 | B 级 ✅ |
| 多少钱能买到好的（没提电池） | 不算 ✅ 闸门挡住 |
| 这个视频拍得挺好看的 | 不算 ✅ |

---

## ⚠️ 生成的词是草稿，不是成品

自动生成的是**通用销售词表 + 行业关键词组合**。它不知道这个行业真正的痛点。

**接单后必做**：
```
拿客户账号扫 200-300 条真实评论
→ 看客户到底怎么说话
→ 把真实表达补进 A/B 级词
```

不做这一步，命中率会很平庸。旅游那套「高反 / 带老人 / 纯玩不购物」就是从真实评论区里长出来的，不是想出来的。

---

## 关键词怎么填（关键）

| 好的关键词 | 坏的关键词 |
|---|---|
| 换电池、锂电池、以旧换新、电瓶车电池 | 电瓶车、电池 |
| 装修报价、全屋定制、旧房改造 | 装修 |
| 贵州研学、亲子夏令营 | 旅游 |

**原则**：填客户在评论区**真的会说的具体词**，不要填大类。太宽会把无关评论全标红。
